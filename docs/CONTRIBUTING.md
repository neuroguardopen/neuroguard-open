# Contributing to NeuroGuard Open

Thank you for your interest in contributing to NeuroGuard Open.

NeuroGuard Open is an open-source research and civic-technology project focused on documenting and studying AI-generated and AI-assisted content that may influence people.

Contributions are welcome from researchers, journalists, developers, designers, digital-rights practitioners, civil society organizations, and other people interested in the project's goals.

---

## Ways to Contribute

You do not need to be a software developer to contribute.

### 1. Document a Case

Help identify and document publicly available examples that may be relevant to the project's research areas.

Useful contributions include:

* Source information
* Context
* Screenshots or archived references
* Relevant dates
* Description of what was observed
* Potential techniques for investigation

Do not submit private or sensitive personal information unnecessarily.

---

### 2. Review Evidence

Help review documented cases.

Reviewers can contribute by:

* Checking sources
* Identifying missing evidence
* Suggesting alternative interpretations
* Identifying unclear claims
* Suggesting additional research
* Pointing out methodological concerns

The goal is constructive review rather than simply agreeing or disagreeing with an interpretation.

---

### 3. Improve the Taxonomy

The NeuroGuard taxonomy is intended to evolve through research and community discussion.

Contributors can propose:

* New categories
* Changes to definitions
* Observable indicators
* Examples
* Research references
* Clarifications
* Overlapping or related concepts

Taxonomy changes should be supported by clear reasoning and, where possible, relevant research.

---

### 4. Add Research

Researchers can contribute:

* Academic papers
* Research reports
* Literature reviews
* Methodological resources
* Datasets
* Relevant public documentation

Research contributions should include enough information for others to locate the original source.

---

### 5. Contribute Code

Developers can help improve:

* Frontend components
* Backend services
* Data structures
* Search
* Evidence workflows
* APIs
* Data export
* Accessibility
* Security
* Documentation

Small improvements are welcome.

---

### 6. Improve Documentation

Documentation contributions are especially valuable.

You can improve:

* Installation instructions
* Methodology
* Taxonomy definitions
* Case documentation
* Research resources
* Developer documentation
* Accessibility
* Translations

---

# Contribution Principles

NeuroGuard follows several principles when evaluating contributions.

## Evidence First

Claims should be supported by available evidence whenever possible.

## Human Judgment

NeuroGuard should not replace human judgment with automated conclusions.

## Transparency

Important assumptions, limitations, and uncertainties should be visible.

## Respectful Review

Disagreement is expected in research. Contributions should focus on evidence and reasoning rather than individuals.

## Privacy

Avoid unnecessary collection or publication of personal information.

## Reproducibility

Where possible, contributions should make research processes understandable and reproducible.

---

# Submitting a Case

Before submitting a case, contributors should consider:

* Is the source publicly accessible?
* Is there enough context to understand the case?
* What exactly was observed?
* What evidence supports the observation?
* What remains uncertain?
* Are there reasonable alternative interpretations?
* Does the case contain unnecessary personal information?

Contributors do not need to prove that content is manipulative before submitting it.

The purpose of the submission process is to create a structured starting point for investigation and research.

---

# Pull Requests

For code and documentation changes:

1. Create a branch for your change.
2. Make the change.
3. Explain what you changed.
4. Explain why the change is useful.
5. Include relevant tests where applicable.
6. Submit a pull request.

Keep changes focused where possible.

---

# Issues

Issues can be used to:

* Report bugs
* Suggest features
* Propose taxonomy changes
* Identify documentation problems
* Discuss research questions
* Report accessibility concerns
* Suggest improvements to the research workflow

Please provide enough context for others to understand the issue.

---

# Responsible Contribution

Please do not use NeuroGuard to:

* Harass individuals
* Publish unnecessary personal information
* Make unsupported accusations
* Target people based on protected characteristics
* Present unverified allegations as established facts
* Circumvent privacy or security protections

When documenting potentially harmful content, preserve appropriate context and clearly distinguish evidence from interpretation.

---

# Getting Started

If you are new to the project, a simple way to contribute is:

**Explore → Read → Document → Review → Discuss → Contribute**

You can start by reading:

* `README.md`
* `docs/methodology.md`
* `docs/taxonomy.md`
* `docs/data-model.md`
* `docs/roadmap.md`
